# IQ Academy native: release engineering (M14)

Use when the owner has an **Expo account/organisation, an Apple Developer account and a Google Play Console account**. You own `eas.json`, `.eas/**`, `docs/release.md`, the store metadata and the release workflows. The owner is terse and expects precision. Never guess store or Expo behaviour: read the current docs (`https://docs.expo.dev/eas/`, `https://docs.expo.dev/eas-update/`, `https://docs.expo.dev/versions/v57.0.0/`) and Apple/Google policy pages, and say **unverified** when you cannot.

Setup as in `00-universal-session.md` §0 and §1. Read `port/NATIVE_DEPS.md` (permission audit), `port/BACKEND.md`, `port/DECISIONS.md` (ADR-011, 012, 013, 014), `app.config.ts`, `eas.json`. Branch `port/m14-<slug>`.

## Ask the owner for (do not invent)
Expo organisation + project (`EAS_PROJECT_ID`) · confirmed iOS bundle id and Android package (default in the repo is `ng.com.promptiq.iqacademy`, derived from the web domain: **confirm before the first store build, they cannot be changed later**) · Apple Team ID, App Store Connect app, an APNs key (or let EAS manage it) · Google Play app, FCM v1 service-account JSON for push · production values for `EXPO_PUBLIC_SUPABASE_URL`, `EXPO_PUBLIC_SUPABASE_ANON_KEY`, `EXPO_PUBLIC_WEB_BASE_URL=https://classes.promptiq.com.ng`, `WEB_HOST=classes.promptiq.com.ng` (stored as EAS environment variables, never committed).

## Tasks
1. **Project link and env.** `eas init`, set `EAS_PROJECT_ID`, create EAS env vars per profile (development/preview/production). Confirm `app.config.ts` produces distinct ids for development/preview (`.development`, `.preview` suffix) so builds install side by side.
2. **Credentials.** iOS (distribution cert, provisioning, push key) and Android (keystore managed by EAS; upload the FCM v1 key). Record the Android release **SHA-256** and the Apple Team ID and hand them to the backend session for `.well-known` files (W1).
3. **Channels and update policy.** `development` / `preview` / `production` channels exist in `eas.json`; `runtimeVersion` policy is `appVersion` (ADR; the docs mark `fingerprint` experimental). Add the **CI fingerprint gate**: on every PR run `npx @expo/fingerprint` (or the current documented equivalent: verify) and fail an OTA publish when the native fingerprint changed without a `version` bump.
4. **OTA runbook (`docs/release.md`).** `eas update --channel preview` for QA, promote to `production` only after sign-off; staged rollout and **rollback** (`eas update:rollback` or republish: verify the current command); what is OTA-safe vs needs a new build (the list in `port/NATIVE_DEPS.md`); how the min-version flag (`app_settings.min_native_version`, backend B7) forces an upgrade; in-app update check on foreground with a prompt and reload.
5. **Workflows.** `.github/workflows`: PR checks already exist (`ci.yml`); add `eas-preview-update.yml` (on merge to `main` → `eas update --channel preview`) and a manual `eas-production.yml` (build + submit) gated by environment approval. Tokens via GitHub secrets.
6. **Export compliance and privacy.** SQLCipher is encryption: answer the export-compliance questions and set `ITSAppUsesNonExemptEncryption` accordingly (explain the reasoning to the owner; do not guess). Apple privacy manifest and "nutrition label", Google Play **Data safety** form: derive answers from `port/NATIVE_DEPS.md` and `port/BACKEND.md` (camera, photos, location while in use, calendar, Face ID, push, account data, payments through Paystack). Review the dev-launcher `NSLocalNetworkUsageDescription` / `NSBonjourServices` keys in the release archive.
7. **Store policy checks (verify against current text):** in-app account deletion (backend B4 must exist), how in-person tuition paid via an external gateway is treated, Android 14+ foreground/notification rules, `POST_NOTIFICATIONS` runtime prompt timing.
8. **Store listing.** Name, subtitle, description, keywords, screenshots (6.9", 6.5", Android phone), icon (1024), feature graphic, support URL, privacy policy URL (ask the owner for the live URL). Draft copy for the owner to approve.
9. **First release path.** `eas build --profile production` for both → internal testing (TestFlight / Play internal) → `eas submit` after approval. Write the go/no-go checklist: all spikes passed (`port/SPIKES.md`), push verified on a physical device, Paystack tested in the live mode the owner chooses, offline scenarios, low-end Android check, account deletion present.

## Output
PR(s) with `eas.json`, workflows, `docs/release.md`, store copy, and a final message of at most 10 lines: what is ready, what is blocked on which account, what the owner must decide.
