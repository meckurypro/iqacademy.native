## Edge Functions (source lives only in Supabase; read it with the connector's `get_edge_function`)
| function | JWT | what native needs to know |
|---|---|---|
| `paystack-init-payment` | yes | POST `{ instalment_id, callback_url? }` → `{ authorization_url, access_code, reference }`. **Returns `reference`.** `callback_url` is honoured only if its origin equals the `SITE_URL` secret, otherwise it silently falls back to `SITE_URL/payment/callback`. Pay instalments in order; older unfinished attempts are marked abandoned |
| `paystack-verify-payment` | yes | POST `{ reference }` → `{ status: succeeded \| pending \| failed \| needs_review }`. **Idempotent, safe to poll.** Already-succeeded payments return `succeeded` without calling Paystack |
| `paystack-webhook` | **no** (Paystack calls it) | completes payments server-side even if the app never reports back |
| `paystack-create-recipient`, `process-payouts`, `process-refund`, `create-staff-user` | yes | admin-only flows (M10a/M10c); read the source before porting |

Consequence for M7b: no deep-link return page is needed. Open `authorization_url` in the in-app browser, keep `reference`, and when the browser closes or the app returns to the foreground, poll `paystack-verify-payment` (e.g. every 2 s for up to 30 s). Pass `callback_url = https://classes.promptiq.com.ng/pay/callback` (same origin as the web). Backend change B6 is therefore **not needed**. Open question for the owner: confirm the `SITE_URL` secret is `https://classes.promptiq.com.ng`.

## Database
- Extensions installed: `pg_cron`, `supabase_vault`, `pgcrypto`, `pg_trgm`, `btree_gist`, `uuid-ossp`, `pg_stat_statements`. **`pg_net` was NOT installed until 2026-10-09 (B2); it is now**: a trigger cannot call an Edge Function until it is enabled (needed for push, B2).
- Realtime publication (`supabase_realtime`): `attendance, checkin_denials, class_messages, class_sessions, notifications, refunds, user_roles`.
- `notifications`: columns `id, user_id, broadcast_id, type, title, body, data jsonb, channel (in_app|email|sms|whatsapp|push), status (pending|sent|failed), send_after, sent_at, read_at, error, created_at, sender_label`. RLS: own rows only (select / update read / delete). A trigger `notifications_sender` fills `sender_label`. **All 54 rows are `channel = in_app`.** Types seen: `class_assigned, role_changed, class_reminder, announcement, class_reminder_staff, run_cancelled, start_changed, custom_class_staff, custom_class_admin, custom_class_invite, pin_changed, class_tomorrow, session_cancelled, centre_earning, offline_receipt, emergency_class_admin, enrolment_active, payment_received`.
- `app_settings(key text pk, value jsonb, ...)`: policy `settings_select` = **readable by everyone**, `settings_admin` = admin only. Keys today: `auto_close_after_hours, auto_issue_certificates, checkin_grace_minutes_after_end, checkin_opens_minutes_before, class_clock_catchup_hours, class_reminder_minutes_before, currency, enrolment_expiry_days, makeup_max_classes, makeup_window_months, min_payout_kobo, offline_payment_details, withdraw_opens_days_before_month_end`. Local reminders (M11a) must read `class_reminder_minutes_before`, never hard-code 60.
- pg_cron jobs: `iqa-class-clock` every minute (`private.class_clock_tick()`), `iqa-class-reminders` 07:00 UTC daily (`remind_upcoming_classes()`), `iqa-run-reminders` 06:00 UTC, `iqa-generate-sessions` 01:00, `iqa-expire-enrolments` 01:30, `iqa-auto-close-classes` hourly :15, `iqa-close-month-statements` monthly.
- PIN: `student_pins(student_id, pin_hash, failed_attempts, locked_until, pw_failed_attempts, pw_locked_until)`; RPCs `pin_required, has_pin, set_pin(p_pin), change_pin(p_new_pin, p_password, p_password_confirm)`. **Staff door PIN is live** (migration 55, web `64bc5f7`): table `staff_pins`, RPCs `has_staff_pin, set_staff_pin(p_pin), verify_staff_pin(p_pin) → 'ok'|'pin_incorrect'|'pin_locked'|'pin_not_set', change_staff_pin(...)`. Instructors and coordinators (not admins) must enter it before the class code/QR is shown or a student is checked in by hand; five wrong PINs pause door tools for 15 minutes; it is separate from the student PIN. `staff_pins` has 0 rows today.
- Migration 53: `mark_attendance` now returns `already_present` instead of accepting any PIN for an already-present student; hand check-in only works from `checkin_opens_minutes_before` before the start to the class end (admins included); only the centre's **coordinator**, an admin or the class's own instructor can mark by hand (directors cannot); **directors no longer get class reminders or the "next class" countdown** (`class_clock_tick`, `my_class_clock`).
- Migration 54: centre staff no longer read raw student tables; they use `centre_students(p_centre_id)` (name, reg number, photo, pack, courses, status, attendance; money columns for directors/admins only). Directors are told when a place is secured. `centre_dashboard` "by weekday" is real attendance. New table `centre_statements` (frozen monthly snapshots with checksum, RLS on) + `centre_statement(p_centre_id, p_month)`; cron `iqa-close-month-statements` runs 00:10 UTC on the 1st.
- `send_class_message(p_session_id, p_body, p_media_path, p_media_name, p_media_mime, p_media_size, p_client_id uuid default null)` **now accepts a client id** (migration 57, re-checked 2026-10-09): `class_messages.client_id` plus unique index `class_messages_sender_client_uniq (sender_id, client_id)`; a repeat returns the existing message id, so it is safe to queue offline (B3 done). Migration 58 fixed a null-instructor case.
- `profiles` has `deleted_at`, `is_active`. Account deletion exists since 2026-10-09 (B4): Edge Function `delete-account` (verify_jwt on, body `{ "confirm": "DELETE" }`) calls the service-role-only RPC `anonymise_account(p_uid)`. The `trg_profiles_protect` trigger reverts `is_active`/`deleted_at`/`email` edits made from a normal user session, which is why this runs as service role. Errors: `admin_cannot_delete` (409), `confirmation_required` (400), `delete_failed` / `delete_incomplete` (500, safe to call again).
- Push (2026-10-09): token table + register/unregister RPCs (B1), and a sender (B2): trigger `trg_notifications_push` (AFTER INSERT on `notifications`, only for `in_app` rows of users who have a registered device) → `pg_net` → Edge Function `send-push` (verify_jwt off; shared secret in Vault `push_webhook_secret`, read back through `get_push_webhook_secret()`, service role only) → Expo Push API. Class reminders are skipped for devices registered with `local_reminders = true`. Tokens Expo reports as `DeviceNotRegistered` are deleted. The secret handshake is tested (right secret 200, wrong 401); the Expo send itself has **not** been exercised with a real device token yet. Not covered: notifications with a future `send_after` are never pushed (none exist today).
- All 95 RPCs the web calls exist in the database (the scanner now reads names inside expressions such as `staff ? "set_staff_pin" : "set_pin"`). Database functions the web does **not** call yet (30): `admin_save_package`, `approve_payout`, `auto_close_overdue_sessions`, `begin_paystack_refund`, `cancel_payout`, `class_message_feed`, `complete_session`, `create_payout_drafts`, `expire_stale_enrolments`, `fail_payout`, `fail_refund`, `generate_class_sessions`, `generate_upcoming_sessions`, `get_user_detail`, `handle_transfer_event`, `instructor_active_classes`, `instructor_message_feed`, `issue_certificate`, `mark_messages_read`, `public_centre_count`, `record_manual_payment`, `record_payment_failure`, `record_payment_success`, `remind_run_endings`, `remind_upcoming_classes`, `review_project`, `revoke_certificate`, `save_course_outline`, `set_user_active`, `verify_certificate`. Most are cron/webhook internals; certificates (`issue_certificate`, `revoke_certificate`, `verify_certificate`), `review_project`, `set_user_active`, `get_user_detail`, `admin_save_package`, `save_course_outline`, `mark_messages_read` look like upcoming web features.
